🚑 Emergency Rollback Runbook

Fast recovery steps for common CCDC mistakes and service outages.

Use this before requesting a full device revert. Try to undo the most recent change first, verify the scored service, and only escalate to a full revert if recovery is no longer practical.

First 60 Seconds — Any Host

1. Confirm what actually broke

Check
Is the service process down, is the port closed, is authentication failing, or is the content wrong?
Compare
Look at your most recent Change Log entry and undo the latest relevant change first.
Verify
Test the service itself after every rollback instead of making several changes at once.

2. Check dependencies before restarting everything

Examples
HTTP may depend on DNS or a database; AD depends heavily on DNS; authentication-based scoring may depend on specific user credentials.
Rule
Do not reboot the whole machine just because one service failed unless you have exhausted targeted recovery.

🧀 Windows — Big Cheesey Rollback

Service stopped or disabled accidentally

Inspect
Win + R → services.msc
Find the affected service and check Status + Startup Type.
Start
Start-Service <ServiceName>
or use Services → right-click → Start.
Restore startup
If you changed Startup Type, return it to the value you recorded before hardening. In PowerShell:
Set-Service -Name <ServiceName> -StartupType Automatic
Use only if you know Automatic was the prior state.
Verify
Get-Service <ServiceName>
netstat -ano
Then test the actual scored service.

Firewall change blocked a required service

Inspect
Win + R → wf.msc → Inbound Rules / Outbound Rules. Sort or filter by recently changed rules.
Rollback
Re-enable the previous allow rule or disable the rule you just created. Prefer reversing only your specific change.
Profiles
Confirm the applicable firewall profile itself was not disabled or misconfigured.
Verify
Get-NetFirewallProfile
Get-NetTCPConnection -State Listen
Then externally test the service.

Password change broke scoring or a dependent service

First
Confirm whether the issue is authentication rather than service availability.
Scoring
If you intentionally changed a required scoring user's password, make sure the Password Change Request was submitted in Quotient.
Service account
If a Windows service uses that account, update its logon credentials through services.msc only if you know the service dependency.
Verify
Test login/authentication using the expected account and then re-test the scored service.

RDP stopped working

Check service
Get-Service TermService
Check access
Review SystemPropertiesRemote, Remote Desktop Users, and RDP firewall rules.
Verify
Confirm TCP 3389 is listening if RDP is expected, then test an authorized account.

DNS / AD authentication suddenly fails

Check services
Verify DNS Server and Active Directory-related services are running.
Check DNS
ipconfig /all
nslookup <domain-or-host>
Undo any recent DNS/IP changes before changing AD itself.
Verify
Test name resolution and then LDAP/domain authentication.

IIS / HTTP stopped serving expected content

Check IIS
Win + R → inetmgr and verify the site + application pool are started.
Restart only IIS
iisreset
Use this only when IIS is confirmed to be the affected service.
Content
If the scoring page content changed, restore the original web files/config instead of replacing the service with a dummy response.
Verify
Request the expected page and confirm the actual content is correct.

😎 Ubuntu — Big Steezy Rollback

Service stopped or disabled accidentally

Inspect
systemctl status <service>
Start
sudo systemctl start <service>
Re-enable
If you disabled startup and know it should be enabled:
sudo systemctl enable <service>
Verify
sudo ss -tulpn
systemctl status <service>
Then test the service externally.

Bad config edit broke a service

Best rollback
Restore the backup copy you made before editing.
Example
sudo cp /etc/ssh/sshd_config.bak /etc/ssh/sshd_config
Validate first
Use the service's syntax check before restarting whenever possible.
Then reload
sudo systemctl reload <service>
Prefer reload over restart when the service supports it.

SSH stopped working after hardening

Do not close
Keep your current working SSH session open while fixing SSH.
Validate
sudo sshd -t
If this reports an error, fix or restore the config before restarting.
Restore
Restore your known-good sshd_config backup if needed.
Reload
sudo systemctl reload ssh
Verify
Open a second SSH session before closing the original one.

UFW blocked a scored service

Inspect
sudo ufw status numbered
Rollback rule
Delete only the rule you just added if it caused the outage:
sudo ufw delete <rule-number>
Restore allow
If a required service needs an allow rule, restore the specific port/service rule rather than disabling UFW entirely.
Verify
sudo ufw status verbose
sudo ss -tulpn

Apache / Nginx stopped working

Apache syntax
sudo apache2ctl configtest
Nginx syntax
sudo nginx -t
Restore config
Restore the known-good site/config file if the test fails.
Reload
sudo systemctl reload apache2
# or
sudo systemctl reload nginx
Verify
Request the expected web page and verify its actual content.

Password / account change broke authentication

Required users
Do not delete the required tryout accounts.
Unlock
If you accidentally locked a required account:
sudo passwd -u <username>
PCR
If you intentionally changed a scoring credential, make sure its Password Change Request was submitted.
Verify
Test the account against the actual scored service.

🧱 VyOS — Big Bedrock Rollback

Firewall / NAT edit broke public service access

Stop
Do not make additional broad firewall changes until you identify the exact rule that changed.
Compare
Use your recorded pre-change configuration or command history to identify the last NAT/firewall edit.
Rollback
Return to configuration mode and remove/reverse only that specific change, then commit.
Verify
Confirm routes, 1:1 NAT, and public reachability of the affected scored service.

Addressing / routing changed accidentally

Priority
Restore the competition-assigned addressing and routes exactly. Do not improvise a new topology.
Verify
Check WAN, LAN, default route, and NAT before troubleshooting individual servers.

🟫 Splunk — Big Sludge Rollback

Your local Splunk search/indexing stops working

Check service
Verify Splunk is running on the Rocky host before changing forwarding or inputs.
Recent change
Undo only your latest local Splunk configuration change if it caused the problem.
Do not touch
Do not disable or remove the Black Team-controlled forwarding from Windows or Ubuntu.
Verify
Confirm new Windows/Ubuntu events appear in your local Splunk searches again.

Common “Undo My Last Change” Checklist

Before escalating

1
Identify the last relevant configuration change.
2
Reverse exactly that change.
3
Restart/reload only the affected service if necessary.
4
Confirm the port is listening.
5
Confirm authentication/content, not just process state.
6
Check logs for the actual failure reason.
7
Record the rollback in the Change Log.

When a Full Device Revert Is Actually Worth Considering

Last resort

Consider it when
You cannot regain administrative access, the service stack is too damaged to repair in reasonable competition time, or compromise is so extensive that targeted recovery is no longer practical.
Before requesting
Capture incident evidence, note what will be lost, and confirm you cannot recover faster manually.
Remember
The tryout packet states that device reverts carry increasing point penalties, so use them strategically rather than reflexively.
